# Sprint 6G — Tool Runtime Execution Layer Report

## Goal

Upgrade the runtime from event-only streaming to structured tool-call execution tracking while preserving the existing runtime, artifact, approval, smoke, and visual gate boundaries.

## Implementation

| Area | Result |
|---|---|
| Runtime tool model | Added `RuntimeToolCall` and `RuntimeToolCallStatus` |
| Runtime store | Added persistent `tool-call-store` backed by runtime sessionStorage state |
| Orchestrator | Streaming ticks now create `SearchKnowledgeBase`, `GeneratePlan`, and `ProduceArtifact` tool records |
| Run Console | Existing Tool Calls panel now renders selector-driven tool name, status, duration, input preview, and output preview |
| Ticket Detail | Execution summary shows current tool, tool progress, last completed tool, and total tools in the artifact summary |
| Approval Center | Queue/detail show originating tool when approval was created by a runtime tool |
| Artifact Viewer | Preview metadata shows `Generated by` when artifact is linked to a tool |

## Store Selectors

- `getToolCallsByRun(runId)`
- `getActiveToolCall(runId)`
- `getCompletedToolCalls(runId)`
- `getToolCallById(toolCallId)`

## Artifact / Approval Linking

| Entity | Link |
|---|---|
| Runtime artifact | `artifact.toolId` |
| Runtime approval | `approval.toolId` |
| Preview model | resolves tool name from `toolId` |

## Smoke Test

Added `scripts/smoke-tool-runtime.mjs` and `npm run smoke:tool-runtime`.

Checks:
- tool created
- tool started
- tool completed
- tool output persisted
- tool linked to artifact
- tool linked to approval
- UI routes render tool linkage
- runtime store survives navigation and reload
